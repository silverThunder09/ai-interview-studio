# 승인된 개발 자동화

이 문서는 목표 흐름과 공통 중단 조건의 진입점이다. **목표는 실제 완성·가동의 증거가 아니다.** 현재 활성 설정과 작업 이력은 신뢰하는 main의 [승인 큐](../.github/approved-loop.json), [머지 정책](../.github/review-policy.json), 상태 원장과 [#35](https://github.com/silverThunder09/ai-interview-studio/issues/35)·실제 PR/CI에서 확인한다. 과거 설계와 검증 근거는 [이력](history/event-loop.md)에 보존한다.

## 목표 흐름

1. 사용자가 큰 기획을 승인하면 기존 범위 안에서 세부 작업을 정리하고 판단을 기록한다. 불명확한 확대·새 유료 API·새 자격증명·미승인 제품 기능은 실행하지 않는다.
2. 이전 작업의 머지와 해당 main CI 성공을 확인한 뒤 승인된 다음 작업을 하나 선택하고 이슈를 하나씩 만든다.
3. 기존 Codex Cloud 계정과 공식 경로로 개발하고 결과를 확인해 일반 PR을 만든다. PR 댓글의 `@codex` 호출이나 채팅 모니터링 예약은 사용하지 않는다.
4. 최신 head/base의 코드와 필수 CI를 검토한다. 리뷰 결함은 중복 여부를 확인해 이슈로 기록하고 기존 PR에서 수정한다. 수정은 최대 3회이며 해결되지 않으면 전체를 멈추고 원인을 남긴다.
5. 사람의 미해결 리뷰·변경 요청을 보존하고 [리뷰·머지 정책](review-automation.md)을 모두 만족할 때만 머지한다. 머지 후 main CI가 실패하면 다음 작업을 멈추고 수정 PR로 복구한다.

## 중복·한도·재시도

- 공식 CLI의 Cloud 전체 목록과 영속 요청·결과 이력을 대조한다. 작업 진행·종료·전달 여부가 불명확하면 새 작업을 중복 발신하지 않는다. 사용자 결정에 따라 지정된 과거 이력은 그대로 보존하며 반영 완료로 추정하지 않는다.
- 사용량 제한이 공식 확인된 경우 1시간 간격의 사용 가능 여부 확인을 목표로 한다. 공식 초기화 시각이 없으면 추정하지 않는다. 실행기가 종료된 뒤에도 확인이 계속되는지는 별도로 입증해야 한다.
- 정확히 연결되고 종료가 확인된 일시 실패만 최초 실패로부터 6시간·24시간·7일 이후 최대 세 번 재시도한다. 종료·전달·원인이 불명확하면 보류한다. 새 발신이 가능한 시점과 실제 재개는 별도 증거로 확인한다.
- CI 성공, 리뷰 통과, 실제 Cloud 시작·결과 수신·실패 후 재개·중복 방지는 각각의 증거를 요구한다. 합성 테스트 성공을 실제 운영 성공으로 표시하지 않는다.

## 현재 구현과 검증 범위

직접 발신·결과 판독·적용·중복 방지 및 재시도 판단의 구성요소와 합성 검사가 존재하지만, 이것만으로 세션 종료 후 상시 실행과 실제 실패 후 재개가 보장되지 않는다. 정확한 설정과 최신 실행 증거를 조회한다. 2026-10-30 확인 당시 [#170](https://github.com/silverThunder09/ai-interview-studio/issues/170)의 main CI readiness 실패 원인은 보존된 기록만으로 확인되지 않았다. 이후 상태를 추정하지 않는다.

`node scripts/review/cloud-preflight.mjs`는 읽기 전용 진단이며 발신이나 재개를 승인하지 않는다. 진단·실제 발신 전에 현재 공식 CLI 로그인과 네트워크를 확인하고 비밀정보를 출력하지 않는다. 완료 영수증·동시성·정확한 현재 SHA 검증과 사람 리뷰 조건은 생략하지 않는다. 실행기·권한·결과 계약을 변경할 때는 기존 세부 경계를 빠뜨리지 않도록 다음 보존 기록의 관련 부분도 확인한다. 상세 이력과 기존 권한 경계는 [기록](history/event-loop.md), [인증 설계 기록](history/event-loop-authentication.md), [역할 분리 설계 기록](history/event-loop-role-separation.md)에 있다.

### 실제 검증과 한계

실제 Cloud 실행·결과·CI·리뷰·머지 및 다음 작업 시작은 각 실행 기록을 확인한다. 이 문서나 설정만으로 상시 실행과 완전 무인 개발 성공을 주장하지 않는다.
