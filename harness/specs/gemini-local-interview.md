# 실사형 3D Gemini 면접관 — 최종 제품 설계안

**상태: 최종 제품 설계 / Phase 1 3D 기반 구현·검증 중.** PR #72는 문서만 머지했다. 이후 사용자 “일단 진행해 봐” 승인으로 Phase 1의 실제 3D 화면·로컬 모델 교체/보존·기본 움직임·관련 테스트/PR을 진행한다. 후속 Gemini 역할 생성·로컬 음성·웹캠·리포트는 요구사항이며 이번에 활성화하지 않는다. 과거 [MVP 1](mvp-01.md)·[MVP 2](mvp-02.md)의 기록을 보존하며 승인·단계 상태는 [architecture](../architecture.md)가 소유한다.

### 사용자 확정 사항 — 2026-10-22 KST

- **목표 기기:** 갤럭시북3 360 15인치. 정확한 SKU·CPU·RAM·GPU/공유 메모리·Windows 버전은 미확인이다. 제품군 이름만으로 세부 사양이나 30FPS·Whisper 속도를 확정하지 않는다. 경량 3D 품질을 초기 기준으로 두고 실제 기기의 두 모델+음성+웹캠 동시 실행 측정 후 품질과 STT 기본 모델을 정한다.
- **모델 설치:** 작은 앱을 먼저 설치하고 최초 설정에서 필요한 3D/음성/STT 모델만 선택 다운로드한다. Windows에 사용 가능한 로컬 음성이 있으면 우선 사용한다. 선택 전에 용량·필요 디스크 공간·출처/버전·라이선스·무결성 검증 정보를 안내하고 진행/취소·재시도·설치 상태를 제공한다. 시작마다 다시 다운로드하지 않는다. 설치된 검증 모델의 로컬 가져오기/재사용을 허용하며 첫 모델 설치 전부터 완전 오프라인 음성/실사 3D가 된다고 표시하지 않는다.
- **모드:** 연습 모드를 별도로 만들지 않고 실전 면접 하나만 제공한다. 준비 화면의 장치 점검은 면접 모드가 아니다. 질문 중 모범 답변/첨삭을 띄우지 않고 개선 피드백은 종료 후 리포트로 제공한다. 접근성·오류 복구를 위한 텍스트 입력/전사 수정·일시정지는 유지한다.
- **답변 제출:** 사용자가 **‘답변 완료’ 버튼**을 눌러 제출한다. VAD/침묵 감지는 녹음 종료 제안에만 사용하며 자동 저장·Gemini 전송·다음 질문을 실행하지 않는다. 로컬 전사를 확인/필요시 수정하고 명시 제출한다. 전사 확인을 별도 연습 모드로 분리하지 않는다.
- **분석 리포트:** 기존 Gemini 키와 사용자가 선택한 접근 가능한 모델을 재사용한다. 질문 생성과 별도 작업/한도로 관리하고 면접 후 전송 미리보기·동의를 받아 생성한다. 새 유료 공급자/별도 API 키는 필수가 아니다. 아래 리포트 AC는 후속 Phase 5 요구사항이며 현재 Phase 1에서는 구현하지 않는다.

## 3. 면접관 A/B와 Gemini

- **A — 기술:** 엄격하고 논리적인 시니어 개발자. Java/Spring/DB/Redis/네트워크/동시성/성능/시스템 설계·기술 선택 근거를 묻는다. 불명확한 설명에 구체적 근거를 요청하고 경험과 기술을 연결하며 난이도를 점진 조절한다.
- **B — 실무·경험:** 친절하지만 근거를 요구한다. 프로젝트 역할·협업·트러블슈팅·성능 개선·의사결정·갈등 해결·성장을 묻고 실제 기여와 문제 해결 과정을 구체화한다. 얼굴로 직무 적합성을 판정하지 않는다.
- 기존 Gemini 키 하나, 단일 요청 큐·동일 면접 기록을 공유한다. 기본은 교대하고 필요하면 동일 면접관이 연속 꼬리질문한다. 두 개의 독립 AI가 같은 내용을 병렬 생성하지 않는다.
- 응답의 speakerId·질문·허용 근거 id를 main에서 검증한다. 발언자가 모델·voice·애니메이션·화면 강조·이름/역할/자막을 함께 결정한다. 문서 명령과 personality는 비신뢰 데이터이며 공통 보안·근거·rubric을 덮어쓰지 못한다.
- 공통 문맥에 선택 근거·최근 질문/답변·주제 진행을 제한된 크기로 포함해 중복을 줄인다. 현재의 한 구절/직전 답변보다 전송 범위가 늘므로 preview/동의를 새로 설계한다. 원문 전체·연락처·경로를 기본 재전송하지 않는다. 로컬 공유 상태가 Gemini 서버의 무료 기억을 뜻하지 않는다.
- 이력서 분석·면접 질문/말투·후속 질문·최종 피드백이 Gemini의 목표 책임이다. 현재 이미 구현된 단일 질문 경로와 구분한다. 새로운 프로젝트/키를 만들도록 요구하지 않고 기존 모델 ID·계정 접근은 사용자가 선택한다.

### 사용량과 비용

면접 시작 전 호출 구조·모델별 횟수/한도·질문/평가 목적을 안내한다. usageMetadata의 입력/출력/캐시/thinking/전체 토큰은 제공된 필드대로 기록하고 누락은 unknown으로 처리한다. 요청 id로 중복 합산/생성을 방지하고 실패/취소·수동 재시도도 한도에 포함한다. API 실패 시 무한 재시도·공급자 자동 대체를 하지 않는다.

현재 12문항·36요청·질문 1,500자·출력 600토큰·30초를 변경의 출발점으로 삼고 공유 문맥/평가용 상한은 구현 스펙에서 승인받는다. 요약을 위한 숨은 유료 호출을 만들지 않는다. explicit cache는 원격 보존·TTL·저장비/삭제 검토 전 기본으로 만들지 않는다.

비용 추정은 실제 모델·가격 출처/유효일·thinking/캐시 과금 규칙으로 계산하며 Google 실제 청구액·세금·환율·예산 보장과 구분한다. 사용량 의미나 가격이 불명확하면 추정 불가다. 실제 유료 테스트는 별도 승인, 개발/CI는 합성 응답만 사용한다. 출처: [모델](https://ai.google.dev/gemini-api/docs/models), [usageMetadata](https://ai.google.dev/api/generate-content), [가격](https://ai.google.dev/gemini-api/docs/pricing), [캐시](https://ai.google.dev/gemini-api/docs/generate-content/caching). 가격/계정 확인을 했다고 주장하지 않는다.

## 4. 실제 3D와 실사형 에셋의 분리

**기본 형식 GLB / glTF 2.0, VRM은 후속 선택 호환.** Three.js·React Three Fiber·GLTFLoader·AnimationMixer·morph targets/blend shapes·Web Audio를 우선 검토한다. drei 등 보조 dependency는 실제 필요할 때만 도입하고 React/Three peer·라이선스·Windows 빌드를 확인한다. 현재 기반 구현은 Three.js를 직접 제어하고 R3F/drei/VRM을 추가하지 않는다. 구체 버전·선택 근거는 architecture를 따른다.

두 개의 실제 3D 인물·정장/비즈니스 캐주얼·피부/헤어·눈 깜빡임·대기/듣기·고개/표정·발언 중 립싱크·카메라/조명·시점 조작을 요구한다. 정적인 사진·2D Talking Face·CSS 입 움직임으로 WebGL/3D 완료를 대체하지 않는다.

완료를 둘로 나눈다.

1. **렌더러/로더 기반:** 실제 3D 모델 두 개 로딩, 사용자 모델 교체, animation/speaker 연결·자원 해제. geometry 인물은 개발/모델 부재/오류 대응용으로만 제공한다.
2. **실사형 면접관 품질:** 라이선스가 확인된 한국인 스타일의 성인 남성·여성 사람 에셋을 실제로 로드해 얼굴·피부·헤어·복장·표정 리깅·입 동작·성능을 검증한다. 단순 geometry만으로 이 완료를 선언하지 않는다. 에셋이 없으면 미확보라고 보고한다.

무료 GLB/glTF 인물, 합법적인 FBX→GLB 변환, MakeHuman, Blender 제작/수정, 재배포 허용 오픈 에셋을 **조사 후보**로 둔다. 한국인 스타일 구현·얼굴 품질·리깅/입 모양·크기/GPU 부담·개인 사용/변경/재배포 조건을 파일별로 비교한다. 아직 특정 모델/라이선스를 확정하지 않았다. 배포 허가가 없으면 Git/Windows exe에 넣지 않고 사용 권한이 있는 로컬 모델을 선택하는 방식으로 제공한다. 사용자 모델 선택이 재배포 허가를 뜻하지 않는다.

### 가져오기·성능 계약

선택 dialog → bounded read → GLB/glTF 구조·버전·자원/텍스처·무결성 확인 → 로컬 renderer 로드 → A/B별 적용. 자기 포함 GLB를 우선 검증하고 glTF의 별도 buffer/texture는 사용자가 허용한 리소스 묶음 안의 상대 경로만 해석한다. traversal·symlink 탈출·원격 URL·임의 파일·스크립트/플러그인 실행을 차단한다. checksum은 파일 일관성일 뿐 안전성·사용권 보증이 아니다. 세부 byte/폴리곤/텍스처 한도는 구현 전 정한다.

공유 WebGL context·해상도/DPR·프레임 상한·경량 품질·화면 숨김 처리를 검토한다. 저사양에서 3D를 2D로 몰래 교체하지 않는다. WebGL 미지원/컨텍스트 손실·모델 실패는 안내하며 텍스트 진행을 유지한다. 30FPS는 목표이며 실측 FPS/환경을 보고한다. CPU/RAM/GPU는 측정 방법과 프로세스를 명시하고 기능 상태를 사용률로 표시하지 않는다. 접근 불가 값은 미측정이다. 교체/이탈/종료 시 geometry/material/texture/animation/controls/renderer·context·worker·음성/track을 정리한다.

## 5. 커스터마이징과 로컬 보존

면접관별 모델·성별 표현·헤어·복장·배경·목소리·속도·personality·질문 유형/난이도를 독립 설정한다. 프리셋은 엄격한 기술/친절한 실무/차분한 시니어/압박 질문/사용자 지정이다. 성격은 표현만 바꾸고 기술 정확성·근거·평가 기준을 왜곡하지 않는다.

모델/voice별 capability를 검사한다. 모든 모델이 얼굴·복장을 바꿀 수 있다고 표시하지 않으며 미지원 설정은 비활성 이유 또는 모델 교체로 제공한다. 선택을 버전 있는 로컬 설정으로 저장하되 API 키는 기존 OS 보호 저장을 유지한다. 설정·기록·3D 모델·음성 모델 경로/수명·삭제를 분리한다. 경로/manifest 손상은 자동 덮어쓰기하지 않고 복구를 안내한다. 재시작 설정 복원이 마이크/카메라/외부 전송 동의를 복원하지 않는다.

## 6. 무료 로컬 TTS와 립싱크

기본 흐름에서 OpenAI TTS 키를 요구하지 않는다. Windows 로컬 음성·한국어 무료 엔진을 우선 검증하고 Piper/MeloTTS 등은 엔진/모델/전이 의존성·배포 조건을 확인한 뒤 선택한다. Windows 설치 음성의 한국어/두 목소리 여부를 실측하며 지원하지 않는 voice·억양을 가능하다고 표시하지 않는다.

질문 생성 → speaker 결정 → 로컬 TTS 생성/재생 → 같은 인물의 립싱크/강조 → 음성 종료 → 답변 대기. 사용자가 시작한 음성 면접에서 자동 질문 읽기를 설계하고 명시 중지·실패/텍스트 대체를 제공한다. 지원 형식/버전·라이선스·무결성을 확인한 로컬 음성 모델만 provider로 추가하며 임의 파일을 실행하지 않는다. 모델 미설치 시 사용자 선택 전 자동 다운로드/유료 fallback하지 않는다.

초기는 실제 오디오 파형/AnalyserNode 진폭 기반 립싱크로 명시하고 viseme/음소 정확성을 과장하지 않는다. Windows TTS 경로가 실제 분석 가능한 stream/bytes를 제공하는지 검증해야 한다. 오디오를 얻지 못한 채 임의 입 움직임만으로 립싱크 성공을 주장하지 않는다. 표정/morph 미지원·음성 실패도 질문/답변 기능을 중단하지 않는다. 같은 질문 재생 캐시·취소/늦은 결과·출력/시간 상한·메모리 처리/해제를 검증한다.

## 7. 로컬 STT와 턴 기반 음성 면접

Whisper.cpp로 키 없는 한국어 전사·마이크 선택·녹음 시작/중지·VAD/발화 종료·전사 표시/수정·답변 제출·텍스트 대체를 제공한다. tiny/base/small **다국어** 후보를 같은 허가된 한국어/Java·Spring·Redis 문장으로 비교하고 정확도·기술 용어·RTF/지연·peak RAM·취소/종료를 실제 Windows에서 측정한 후 기본 모델을 정한다. UI thread에서 추론하지 않는다. 현재 WebM/Opus를 엔진 PCM으로 변환하는 경로·decoder/임시 파일 필요성도 별도 검증한다.

기본 상태는 준비 → 질문 생성 → 면접관 발언 → 사용자 답변 → 전사/검토 → 후속 질문 생성 → 전환/연속 질문 → 종료/피드백이며 일시정지/오류·취소를 분리한다. operation/session/question/epoch로 중복 질문/제출·늦은 결과를 거절한다. 침묵은 종료 제안이며 기본적으로 확인 없이 답변을 저장/전송하지 않는다. 턴 기반 사용성을 먼저 완성하고 TTS 끼어들기는 후속이다. 에코·장치 중단·동시 자원·재개/종료를 검증한다.

## 8. 웹캠·MediaPipe·상태별 화면

웹캠은 별도 동의·장치/미러 선택·시작/중지·권한 거절·장치 제거·종료 track 해제가 필요하다. 현재 카메라 deny를 전체 허용으로 바꾸지 않고 사용자 시작·정확한 창/프레임/URL의 video 요청만 한정 허용한다. MediaPipe의 로컬 얼굴 존재·위치/크기·구도·head pose·이탈/대략적 정렬 관찰은 후속이다. 정확한 시선 추적·감정/자신감/거짓말/인성/지능/합격/직무 적합성 판정은 하지 않는다. 영상 지표는 기술 답변 점수와 분리하고 Gemini 전송·기본 녹화를 하지 않는다. 녹화는 별도 선택/승인·동의·보존/삭제 계약 후다.

| 화면/상태 | 표시·전환 |
| --- | --- |
| 준비 | 이력서 검토·기존 Gemini 등록/모델(등록과 인증 성공 구분), A/B 프리셋, 로컬 voice/model, 마이크/카메라 테스트, 실전 면접 시작·난이도 |
| 기본 배치 | 왼쪽 홈/이력서/시작/기록/설정/프리셋, 중앙 위 두 3D 모델·이름/역할/상태, 오른쪽 웹캠/카메라·마이크/선택 관찰, 아래 질문/자막/전사/제출·장치/자막/일시정지/종료 |
| 면접관 질문 | 실제 speaker 모델 확대/강조·다른 인물 대기, 목소리·입/표정·자막 결합 |
| 사용자 답변 | 웹캠·입력 상태·답변 시간 강조, 두 인물 듣기 상태 |
| 질문 생성/지연 | 두 인물 대기·진행/지연 안내, 이전 입력 유지 |
| 종료 | 완료 상태/animation·리포트 생성 여부/실패 구분·결과로 이동; 장치/작업 종료 |

화면 전환은 실제 3D가 렌더링되는 상태에서 검증한다. 한국어·다크/라이트·청록 강조·키보드/초점·상태 알림·모션 감소·저사양 옵션을 유지한다. 정적 디자인 예시는 실제 실행 증거가 아니다.

## 9. Gemini 면접 분석 리포트

리포트는 실전 면접의 핵심 완료 범위다. 제출된 질문/답변과 사용자가 허용한 이력서 근거를 기존 Gemini 키로 분석한다. 로컬 얼굴 관찰·원본 음성/영상은 입력에 포함하지 않는다. 면접 종료 시 자동 외부 전송하지 않고 결과 화면에서 **‘Gemini 분석 리포트 생성’**을 선택하도록 한다. 요청 전에 실제로 보낼 질문/답변·근거·모델·추가 호출/비용 가능성을 보여주고 별도 동의를 받는다. 동의가 없거나 키/인터넷이 없어도 면접 기록은 로컬에서 열 수 있다.

| 리포트 항목 | 요구 내용 |
| --- | --- |
| 전체 요약 | 다룬 주제·답변 경향·근거 있는 강점과 우선 보완점. 중도 종료/미답변은 명시 |
| 질문별 분석 | 질문/답변 id·면접관 A/B·제출 원문·인용 근거·잘한 점·빠진 설명·개선 방향 |
| 기술 역량 | 정확성·질문 관련성·기술 선택 이유·문제 해결 과정. 정해진 rubric과 답변 근거를 연결 |
| 경험·협업 | 실제 역할/기여·의사결정·트러블슈팅·갈등 해결 설명의 구체성. 확인되지 않은 경험을 만들지 않음 |
| 개선 예시·다음 준비 | 기존 답변을 다듬은 예시임을 표시하고 추가 사실이 필요한 곳은 질문/빈칸으로 구분. 학습 키워드와 준비 우선순위 |
| 생성 정보·한계 | 모델 id·생성 시각·rubric/스키마 버전·입력 범위·사용량/추정 비용·AI 분석 표시. 정보 부족은 평가 불가 |

합격 확률·채용 적합성·감정/자신감/거짓말/인성/지능을 판정하지 않는다. 얼굴 지표를 답변 분석에 합산하지 않는다. 수치 점수·가중치는 이번에 임의 확정하지 않고 초기에는 항목별 근거·강점·보완점 중심으로 설계한다. 과거 리포트 비교·시각화 확장은 후속이며 별도 연습 모드를 요구하지 않는다.

### 생성·보존·실패 AC

1. 종료한 면접의 제출 완료 snapshot과 허용 근거만 사용한다. 질문/답변 id·인용 내용이 실제 snapshot에 존재하는지 main에서 검증하고 형식/근거가 틀린 응답을 정상 결과로 저장하지 않는다. 이력서/답변의 지시는 평가 규칙을 변경하지 못한다.
2. 질문과 구분된 report request id·입력 hash·모델/rubric 버전으로 중복 클릭·늦은 응답을 제어한다. 같은 입력의 완성 리포트는 재호출 없이 열고, 재생성은 추가 전송/비용을 안내한 명시 요청으로만 한다. 재생성 실패는 기존 성공 리포트를 지우지 않는다.
3. 리포트용 입력/출력 토큰·timeout·호출 수 상한은 질문의 기존 600토큰 제한과 구분해 구현 전 확정한다. 세션 공통 호출 예산에 포함하고, 너무 긴 입력은 숨은 요약/분할 유료 호출이나 묵시적 잘라내기 대신 범위 축소를 안내한다. 사용량 누락은 unknown이며 실제 비용/개인 자료를 개발 검증에 사용하지 않는다.
4. 생성 대기·진행·취소·성공·실패를 구분한다. quota/권한/네트워크/timeout/잘못된 형식·취소 시 원래 면접 기록을 보존하고 수동 재시도를 제공한다. 무한/숨은 재시도·공급자 대체를 하지 않는다.
5. 검증된 결과와 생성 정보를 기존 세션에 연결해 로컬 SQLite에 원자적으로 저장한다. migration 실패 rollback·재시작 후 조회·세션 삭제 시 연계 삭제를 검증한다. 현재 평문 DB임을 안내하고 원문 답변/리포트를 CI/진단 로그에 남기지 않는다. 내보내기는 사용자가 선택한 리포트와 위치에만 수행한다.
6. 합성 Gemini 응답으로 정상/증거 부족/미답변/중도 종료/허위 인용/잘못된 형식/상한 초과/중복/취소/실패·재시도/기존 리포트 보존·조회/삭제를 검증한다. 실제 Gemini 품질·요금·사용자 기록 분석은 별도 미검증으로 남긴다.

## 11. 단계별 완료·테스트 계획

정확한 Phase 순서는 [로드맵](../architecture.md#스펙-구현-순서--단계별-승인검증)을 따른다. Phase 1은 실제 두 3D 모델/GLB·glTF/교체·animation/레이아웃, 2는 Gemini 두 역할/문맥/usage, 3은 로컬 TTS/립싱크, 4는 웹캠/상태 화면, 5는 Whisper/STT/명시 답변 제출과 Gemini 분석 리포트로 면접 종료까지 완성, 6은 관찰/리포트 비교·시각화/커스터마이징 확장/끼어들기/설치 관리 확장이다. 선택 모델의 최초 설치·검증은 해당 기능 Phase에서 제공하며 Phase 6까지 미루지 않는다. VRM은 필수 단계가 아니다.

각 구현 PR에서 npm run check/build·관련 unit·실제 Electron smoke·Windows 원본/패키지 검증을 수행한다. 실제 3D 로드/교체·발언 전환·음성/립싱크·권한 거절·device/worker/child/GPU 정리·DB/기존 면접 회귀를 영향에 맞게 검증한다. 합성 문서/허가된 모델·오디오/frame·mock Gemini만 CI에 사용한다. 실물 Windows GPU·카메라·마이크·스피커/한국어 품질·실제 계정 접근은 별도 미검증으로 명시한다.

## Phase 1 기반의 현재 제한

기본 인물은 자체 제작 geometry이며 실사형 에셋이 아니다. A/B 모델별 파일은 native dialog로 고른 자기 포함 GLB/glTF만 허용한다. 20MiB/JSON 1MiB·node 256개·배치/모프를 포함한 geometry 비용 20만·이미지 최대 8개/2048px/전체 약 8M pixels로 제한한다. sparse·압축 확장·외부 경로/URL·여러 파일 묶음은 이번 기반에서 거절한다. 검증한 메모리 buffer와 Blob의 직접 bitmap decode를 GLTFLoader에 연결하며 renderer fetch/Blob URL 허용을 늘리지 않는다.

실제 로딩 성공 후 앱 사본만 슬롯별 고정 위치에 원자 저장한다. 무결성 해시·재검증·재시작 복원·실패 시 기존 사본 보존·기본 모델 전환을 검증한다. 모델 라이선스는 사용자가 보유해야 하며 파일 형식/해시 검증을 사용권 보증으로 표현하지 않는다. `blink/eyeclose`, `jawOpen/mouthOpen/aa/viseme_aa`, `Head` bone 등 지원 가능한 rig만 제어하고 미지원 항목을 표시한다. 무음 입 동작 확인은 음량 기반 립싱크가 아니며 실제 음성 연동은 Phase 3이다.
