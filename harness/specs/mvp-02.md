# MVP 2 — 음성 면접

이 문서는 기존 OpenAI 전사·질문 읽기의 구현·승인·한도를 보존한다. 2026-10-22 KST 요청한 무료 로컬 TTS·Whisper.cpp·실시간 턴의 후속 설계는 [리팩터링 스펙](gemini-local-interview.md), 새 Phase 순서는 [로드맵](../architecture.md)이 소유한다. 로컬 엔진·모델·카메라는 아직 설치/구현하지 않았으며 이 문서의 과거 승인으로 자동 활성화하지 않는다.

상태: **음성 입력·현재 질문 읽기 구현 및 자동 검증 완료**. 2026-10-17 KST 사용자가 마이크 사용·OpenAI 전사·검토/수정·직접 답변 제출과 한도/문서·push/PR/검증 후 머지를 승인했고 PR #19로 완료했다. 2026-10-18 KST 테스트 기록/컨텍스트 하네스 정리를 먼저 완료한 뒤 사용자가 다음 단계 진행을 재지시해, 앞서 제안한 질문 음성 읽기 경계를 구현한다. 개발 검증은 합성 입력/응답만 사용하며 실제 유료 호출·개인 음성 전송·실시간 대화·카메라·공개 release는 제외한다.

## 첫 구현 제안: 녹음 후 전사하고 답변 검토

- 사용자가 직접 시작/중지한 한 답변의 음성을 텍스트로 바꾸고 기존 면접 답변 입력에 적용한다. 기존 OpenAI·Claude·Gemini 질문 생성과 준비된 질문 모드를 그대로 이용한다. 로컬 모델은 추가하지 않는다.
- 음성 전사는 우선 OpenAI의 고정 `https://api.openai.com/v1/audio/transcriptions` endpoint를 제안한다. 질문 생성 서비스와 전사 서비스를 구분해 표시한다. Claude/Gemini로 면접하더라도 음성 전사를 선택하면 OpenAI로 음성이 간다는 사실을 표시한다.
- 전사 모델 ID는 사용자 계정에서 이용 가능한 모델을 앱에 직접 입력한다. 기본 모델·가격·계정 권한·무료 여부를 추측하지 않으며 등록 시 인증 호출을 하지 않는다. 실제 구현 시 선택한 모델의 지원 형식과 출력 제한을 재확인한다.
- OpenAI 키는 기존 main 메모리 보관 정책을 사용한다. renderer에 저장된 키를 반환하지 않으며 전사 요청에 이력서·질문·이전 답변·파일 경로를 넣지 않는다. 필요한 모델/언어/응답 형식만 추가한다.
- 첫 단계에서 음성 원본을 디스크/SQLite/로그에 저장하지 않는다. 사용자가 검토하고 제출한 답변 텍스트만 기존 로컬 저장 동의와 기록 정책에 따른다.
- 자동 녹음·자동 업로드·자동 답변 제출·질문 음성 재생·실시간 스트리밍·끼어들기는 이번 첫 단계에서 제외한다. 카메라·아바타·음성 감정/인물 평가·외부 음성 파일 불러오기·음성 export도 제외한다. 첫 단계만 완료하고 실시간 음성 면접 전체를 완료했다고 표현하지 않는다.

## 사용자 흐름

1. 진행 중인 텍스트 면접에서 사용자가 음성 입력을 선택한다. 기본은 기존 텍스트 입력이다.
2. 마이크 사용 목적과 메모리 보관/폐기 범위를 확인하고 `녹음 시작`을 누른 시점에만 권한과 스트림을 요청한다. OS 권한 거절/장치 없음/사용 중은 구분해 안내하고 텍스트 입력은 유지한다.
3. 녹음 시간과 시작/중지/폐기를 표시한다. `녹음 중지`는 즉시 트랙을 해제하고 최종 버퍼를 준비할 뿐 외부 전송하지 않는다. `폐기`는 버퍼와 참조를 비운다.
4. 서비스·모델·음성 길이/크기·전송 범위·과금/서비스 보존 정책을 보여준다. 별도 체크 동의 후 `동의한 음성 전사`를 눌러 한 번만 보낸다. 녹음이나 모델이 바뀌면 동의를 해제한다.
5. 결과는 별도 검토란에 표시한다. 기존 입력을 덮어쓰지 않는다. 사용자가 수정 후 `답변 입력에 적용`을 눌렀을 때만 적용하며, 기존 입력이 있으면 교체를 명시적으로 확인한다. 적용은 저장이나 AI 질문 생성이 아니다.
6. 사용자가 기존 답변 제출 버튼을 눌러 저장한다. AI 질문 모드라면 이후 텍스트 전송 동의를 별도로 받는다. 전사 동의를 질문 생성 동의로 재사용하지 않는다.

## 데이터·권한 경계

- sandbox renderer: MediaRecorder/오디오 트랙과 메모리 버퍼, 검토 화면을 관리한다. 새 SDK·브라우저 음성 인식·OS 음성 서비스·임의 endpoint를 사용하지 않는다. renderer의 외부 네트워크 차단과 Node 격리를 유지한다.
- main: 앱의 정확한 창·메인 프레임·URL·일회성 사용자 시작 상태·audio-only 요청을 검증한 경우에만 해당 작업의 마이크 요청을 허용한다. 카메라·화면·다른 창/프레임·백그라운드 장치 요청은 계속 거절한다. Electron의 권한 확인과 요청 경로를 모두 검증한다. 녹음 선택 상태는 앱 재시작 시 초기화한다.
- preload/main IPC: 한도 내 오디오 bytes와 허용된 메타데이터만 받는 좁은 API를 추가한다. 파일 경로·임의 URL·API 키 조회·SQL·범용 invoke는 추가하지 않는다. 녹음 상한·메타데이터는 renderer 값을 그대로 신뢰하지 않고 검증한다.
- 전사 transport는 main 전용 native fetch와 기존 메모리 키만 사용한다. 고정 HTTPS endpoint, redirect 거절, cookie 생략, cache no-store, 제한된 응답 읽기를 적용한다. 입력/응답/예외/로그에 민감정보를 노출하지 않는다. 자동 재시도·공급자 전환은 없다.
- 중지/취소/장치 제거/화면 이탈/질문 변경/세션 삭제/창 닫기에서 트랙·타이머·리스너·버퍼 참조를 정리한다. 권한 요청이 화면 이탈 후 늦게 성공해도 도착한 트랙을 즉시 해제한다. JS·OS 메모리의 즉시 안전 삭제를 보증하지 않는다.
- 허용되는 최소 마이크 경계는 현재 장치 거절 동작의 명시적 변경이다. 승인 후에도 sandbox/카메라 거절/IPC 송신자 검사/필수 CI를 완화하지 않는다.

## 승인된 첫 단계 한도

| 대상 | 초기 상한과 처리 |
| --- | --- |
| 녹음 | 답변당 60초·8MiB 중 먼저 도달한 한도에서 중지, 자동 전송 없음 |
| 입력 형식 | 우선 WebM/Opus; 런타임 지원 검사 및 main의 서명/최소 구조 검증. 지원하지 않는 환경은 텍스트 입력 안내 |
| 전사 대기 | 요청당 30초, 취소 시 늦은 응답 폐기 |
| 전사 응답 | 읽기 최대 64KiB, 빈 값/NUL/잘못된 JSON 거절 |
| 검토 텍스트 | 기존 모드의 답변 한도 적용: 외부 AI 2,000자·준비된 질문 10,000자. 초과 결과를 몰래 잘라 적용하지 않고 검토·수정 안내 |
| 호출 수 | 앱 실행당 전사 최대 36회, 실패/취소/수동 재시도 포함. 기존 질문 생성 36회와 별도로 표시하며 금액 상한으로 표현하지 않음 |
| 동시 작업 | 한 창에서 녹음/전사 하나만, 진행 중 중복 시작·제출 거절 |

60초는 앱의 녹음 타이머 상한이다. 비신뢰 renderer의 신고 시간만으로 원본 오디오 재생 길이를 증명한다고 표현하지 않는다. main은 bytes·형식과 요청 상한을 별도로 강제한다. 사용자는 서비스 콘솔의 예산/보존 정책도 확인한다. 취소는 이미 발생한 전송·요금을 되돌리지 못한다.

## 진행 상태·취소·재시도 계약

`대기 → 권한 요청 → 녹음 중 → 전송 전 검토 → 전사 중 → 전사 검토 → 답변에 적용`을 구분한다. 기존 답변과 질문 상태는 독립적으로 보존한다.

- 각 녹음/전사 시도는 작업 ID와 현재 세션/질문에 연결한다. 취소·이탈·새 시도 후 이전 작업의 성공/실패 이벤트를 버린다. 서로 다른 질문에 전사를 적용하지 않는다.
- 권한 거절/장치 없음/녹음 실패는 기존 텍스트 입력을 보존한다. 사용자 재시작 없이는 장치를 다시 열지 않는다. 장치 중단으로 불완전해진 녹음은 자동 전송하지 않는다.
- 인증/429/네트워크/시간 초과/잘못된 전사는 정형 오류로 표시한다. 기존 질문·답변 입력을 유지한다. 사용자는 메모리 버퍼가 유효할 때에만 명시적으로 재전송하거나 폐기할 수 있다. 취소/폐기 후에는 재녹음한다.
- 키 변경/비우기는 진행 중 전사를 취소한다. 키 재등록은 전사를 자동 재개하거나 호출 예산을 초기화하지 않는다. 질문 생성과 전사 오류/잔여 요청을 구분한다.
- 전사 대기 동안 SQLite transaction을 열거나 답변을 저장하지 않는다. 전사 성공/취소만으로 질문 번호를 진행하지 않는다.

## 검증과 완료 기준

- 순수 계약/단위: 허용 키·bytes/형식/크기/모델 검증, 동의 누락, 중복·잘못된 ID·다른 질문의 늦은 결과 거절, 오류 원문/secret 비노출, 출력/호출 한도.
- 모의 장치: 권한 거절/없음/사용 중, 중지/시간·크기 한도, 권한 요청 중 이탈/늦은 허용, 장치 제거, 모든 종료 경로의 track.stop/timer/listener 정리. 합성 오디오만 사용한다.
- 모의 transport: 정확한 endpoint/header/multipart, 이력서·이전 답변·파일 경로·키 body 비포함, 취소/시간 초과/429/인증/과대·빈 응답, 수동 재시도당 한 호출, 늦은 완료 폐기.
- Windows source/packaged smoke: UI→IPC→합성 전사→검토/수정→명시 적용→기존 답변 저장·재시작. 기존 입력 보존과 동의 분리, 카메라·비허용 창/프레임의 미디어 요청 거절, sandbox 유지, DB 회귀를 확인한다. 가짜 장치/요청을 실제 마이크나 서비스 성공으로 표현하지 않는다.
- 변경 후 typecheck/lint/관련 unit tests와 build, 원격 PR의 필수 checks/package/pr-policy 및 정확한 CI 증거를 확인한다. 변경 없는 상태에서 검사를 무한 반복하지 않는다.
- Windows 실제 하드웨어: 사용자가 내려받은 앱에서 마이크/OS 권한/한국어 발화/중지·재시작을 확인한다. 실제 서비스 인증·음질·전사 정확도·과금은 별도 사용자 선택 검증이며 개발자/CI가 대신 실제 개인 음성을 전송하지 않는다.

## 구현·PR 순서와 필요한 승인

1. 위 첫 단계와 한도 및 세 문서 변경은 사용자가 승인했다. 기존 리뷰 정책·스킬·CI·의존성 변경 승인은 포함하지 않는다.
2. 승인 후 기능별 계약/취소 수명주기·모의 transport, 좁은 IPC/마이크 권한, 녹음/전사 검토 UI를 작은 검토 가능한 커밋으로 구현한다. 현재 첫 단계에 필요한 구현만 추가하며 사용하지 않는 범용 프레임워크는 만들지 않는다.
3. 승인된 동일 작업의 Draft PR에 통합하고 실제 검사/합성 Windows smoke, 코드·PR 리뷰와 CI 증거를 확인한다. 보호 문서는 위 승인한 세 문서만 변경한다. 정책의 PR/수정 횟수 상한과 사람의 미해결 리뷰를 지킨다.
4. 질문 음성 재생/중지는 아래 후속 단계로 진행한다. 끼어들기·실시간 전사/대화는 별도 전송·비용·리소스 경계를 정한 뒤 제안하며 자동 활성화하지 않는다.

## 후속 단계 — 현재 질문 음성 읽기

2026-10-18 KST 사용자는 “위 TTS 기능·문서의 push·PR·검증 후 머지 승인”으로 현재 질문의 OpenAI speech 전송 구현, 메모리 재생/중지, 관련 스펙·보안·아키텍처/테스트 기록 갱신을 명시적으로 승인했다. 앱에서의 개별 전송 동의는 여전히 필요하며 개발 중 실제 유료 호출·개인 자료 전송은 승인에 포함하지 않는다.

- 현재 질문 전송 미리보기 → OpenAI 모델 ID/기본 제공 voice 선택 → 별도 전송·과금 동의 → 생성 → 사용자 재생/중지. AI 합성 음성임을 표시하며 자동 생성/재생하지 않는다. 질문에 포함된 개인 내용도 전송될 수 있음을 알린다.
- main이 실제 SQLite의 현재 미답변 질문과 preview를 대조한다. 고정 `https://api.openai.com/v1/audio/speech`에 질문 본문·모델·기본 제공 voice·MP3 설정만 보낸다. 원문 이력서·별도 근거·답변·경로를 body에 추가하지 않는다. 기존 main 메모리 OpenAI 키를 header에만 사용한다.
- 질문 최대 1,500자(초과 시 거절·텍스트 유지), 생성 30초·응답 8MiB·실행당 별도 생성 36회(실패/취소/수동 재시도 포함), 재생 최대 90초. 모델/voice의 실제 접근 권한·한국어 품질·요금은 고정하거나 추측하지 않는다. 상한은 금액 보장이 아니며 취소 전 전송·요금은 되돌리지 못한다.
- MP3 MIME·ID3 길이/연속 frame 경계를 main에서 확인한 bytes만 좁은 IPC로 반환한다. 이는 전체 음성 품질 보증이 아니며 renderer의 기본 디코더가 실제 재생을 처리한다. `media-src blob:`만 열고 임의 네트워크/파일 URL·renderer 외부 통신·카메라는 차단한다.
- 같은 작업의 중복 생성은 진행 중 promise/성공 메모리 결과를 재사용한다. 다른 내용의 같은 작업 ID는 거절한다. UI의 동일 오디오 재생은 새 요청을 하지 않는다. 모델/voice·질문 변경·폐기·이탈 시 bytes·메모리 URL을 비우고 파일/DB/export는 제공하지 않는다.
- 키 변경/비우기·취소·질문 변경·삭제·종료는 생성 취소/늦은 결과 폐기. 생성 대기 중 DB transaction 없음. 재생 실패·429·인증·시간 초과는 정형 오류이며 기존 질문/답변을 진행하거나 지우지 않는다. 자동 재시도·공급자 대체는 없다.
- 재생 중지·끝·이탈에서 pause/src 해제·Blob URL revoke·timer/listener를 정리한다. 음성 읽기/입력을 전환하면 이전 UI와 작업을 정리해 재생/녹음을 함께 시작하지 않는다. 생성/재생 중에는 답변 제출을 막고, 중지/취소 후 직접 제출할 수 있다.
- 검증: 합성 MP3·fetch, 실제 임시 SQLite, 응답/한도/동의/중복/취소·늦은 결과와 플레이어 자원 해제 테스트. Windows 원본/패키지에서 실제 MP3 디코딩·사용자 재생/중지·추가 호출 없는 재생·녹음 상호 배제·외부 미디어 CSP 차단을 확인한다. 실제 유료 API/개인 자료/사용자 장치 품질은 개발 검증에서 제외한다.
